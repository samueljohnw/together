## Project

"Together" is a shared space for one household (typically two people): **to-dos** and **threads**, each with its own message thread and file attachments. Closed items live on Account › Closed Items and can be re-opened.

- **Auth:** each member has their own login (`/login`, session auth, `auth` middleware on everything else). There is no sign-up; add members with `php artisan together:add-member {email} {name}`. Every signed-in user belongs to the single household, so there is no per-item authorization beyond being signed in.
- **Data model:** to-dos and threads share one `items` table (`App\Enums\ItemKind`: `todo` / `thread`). `closed_at`/`closed_by_id` mark closed items; `last_activity_at` orders the workspace. `messages` belong to an item; each message is either a text `body` or a single attachment (stored privately on the default disk under `attachments/`, downloaded via the `messages.attachment` route).
- **Rendering:** the pages are Blade shells that embed their initial data as JSON (`<script data-initial-items>` / `data-initial-closed-items`). `resources/js/app.js` (vanilla JS, no framework) renders everything from that JSON and from the JSON routes (`items.*`, `closed-items.*`), which return `ItemResource` / `MessageResource`. These resources are viewer-relative: the current user is shown as "You", and `is_mine` drives chat alignment.
- **Live updates:** the workspace polls `GET /items` and the open item (`GET /items/{id}`) every 5 seconds while the tab is visible. There are no websockets.
- **Push:** Web Push (VAPID; `php artisan together:push-keys`, env `TOGETHER_VAPID_*`). Subscriptions belong to a user. `SendActivityPushNotifications` is dispatched *after the response* (no queue worker needed) whenever an item or message is created, and notifies only the other members' devices. `public/sw.js` shows a generic notification (no payload).
- The JS finds DOM elements through `data-*` hooks. In the item windows, `data-todo-close`/`data-thread-close` (the ✕) dismiss the window, while `data-*-close-item` (the "Close" text button) closes the item. Keep these hooks in sync when you edit the Blade markup.
- Styling is Tailwind v4 (CSS-first config in `resources/css/app.css` via `@theme`; there is no `tailwind.config.js`).

## Commands

- `composer setup`: first-time install (deps, `.env`, key, migrate, npm build).
- `composer dev` (= `php artisan dev`): runs `serve`, `queue:listen`, `pail` and `vite` together. See `php artisan dev:list`.
- `npm run build`: production asset build. Needed if Vite manifest errors appear.
- `composer test` or `php artisan test --compact`: full suite. For a single test, use `php artisan test --compact tests/Feature/ExampleTest.php` or `--filter=name`.
- `vendor/bin/pint --dirty --format agent`: format changed PHP files.

The database is SQLite (`database/database.sqlite`). `php artisan db:seed` creates demo members `alex@example.com` and `sam@example.com` (password `password`) with sample items. Tests use in-memory SQLite (see `phpunit.xml`), and `LazilyRefreshDatabase` is applied to all Feature tests in `tests/Pest.php`. PHP's default `upload_max_filesize` (2M) is lower than the app's 20 MB attachment limit, so raise it in php.ini to accept larger files.
